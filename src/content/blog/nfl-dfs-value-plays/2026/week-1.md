## Why this board is DK-FPPG-based this week

Every projection on this site is normally built from this site's own
model — recent-form data, run through real depth-chart and team-change
discounts (see the August 30 update this post used to carry). That model
has a real limitation right now, specific to this exact moment in the
season: with zero 2026 games played yet, its "recent form" number is
necessarily built 100% from last season. The depth-chart and team-change
discounts help correct for known role changes, but they don't manufacture
real current-season signal that doesn't exist yet.

So for this one update, the board below is ranked and valued by **DK's
own published FPPG** instead — a deliberate, temporary swap, not a
permanent change to how this site projects players. This isn't a clean
fix either: DK's own methodology isn't published, and a direct check
found it carries the *same* stale-prior-team problem for some players
that this site's own model had before its August 30 fix. Three names
below — Darren Waller, Kyler Murray, and Wan'Dale Robinson — are back on
this board for exactly that reason: DK's own number doesn't apply the
real depth-chart/team-change discount this site's model does for them.
Included deliberately, with this note, not quietly.

This site's own model projection is shown alongside DK's FPPG for every
player below, so the gap stays visible either way. Revisit this call
once real 2026 results exist and this site's own recent-form data has
actual current-season signal to lean on again — likely by Week 3 or 4.

## FAQ

### Why is this board ranked by DK's own FPPG instead of this site's own model this week?

Because this site's own model's "recent form" data is necessarily 100%
built from last season this early — there are zero 2026 games on file
yet. Rather than present that as more current than it actually is, this
one update leans on DK's own published number instead, with this site's
own model projection still shown for direct comparison. See "Why this
board is DK-FPPG-based this week" above for the full reasoning, including
its own real limitation.

### Doesn't DK's own number have the same problem?

Partly, yes — and that's disclosed, not hidden. A direct check found
DK's FPPG clearly adjusts for some players whose team or role changed
this offseason, but not others. Darren Waller, Kyler Murray, and Wan'Dale
Robinson are on this board specifically because DK's own number doesn't
apply the same real depth-chart/team-change discount this site's model
does for them.

### Why isn't every high-value name on this board a pick?

Because "value" only measures points against salary — it doesn't know
whether a player's current role actually supports getting those points.
This week's board is checked against real, team-reported depth-chart data
before any role gets described as a "starter" or similar; when that data
doesn't back the number up, this post says so directly instead of
quietly including the name anyway.

### Does an injury designation actually change the numbers?

Yes, in two ways now. In this site's own model, a real "Questionable,"
"Doubtful," or "Out" status pulls a player's own-model projection down
before they'd show up on this site's normal board. And as of September
10, an "Out" designation excludes a player from this board outright,
regardless of which number (DK's or this site's) is doing the ranking —
DK's own FPPG doesn't adjust for game-day status on its own, so that
exclusion is applied directly rather than assumed. Any remaining
designation is still shown as a plain label so you can weigh it
yourself.

### Does the matchup affect this week's rankings?

Not this week — DK's own FPPG doesn't factor in this site's matchup
multiplier at all, so it plays no role in this particular board's
ranking. It still applies to this site's own model projection shown
alongside each player.

### When does this get updated before kickoff?

Whenever a salary, projection, or depth-chart change is significant
enough to matter. Check the "as of" line at the top of the post — it
always reflects the most recent real update, not just when this was
first published.
